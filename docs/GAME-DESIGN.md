# SCHOOL_RAN｜遊戲設計規格

## 方向與視覺

- 類型：2D 橫幅／網頁 MMORPG，參考《亂 ONLINE》的校園題材與養成、戰鬥、社交循環。
- 視角：正交俯視角、四方向移動，地圖採 GBA 掌機 RPG 的 tile-based 表現；不是等角或 3D。
- 美術：GBA 16-bit 像素風。環境使用簡潔、易讀的 tile；人物採較大且細節更豐富的 Q 版約 3 頭身比例，確保換裝一眼可辨。
- 人物尺寸建議先以 48×64 px 作為單方向單幀的試作基準，最終依角色比例與動畫需求調整。
- 地圖 tile 建議先以 16×16 px 為基準；大型物件可由多 tile 組合。

## 玩家角色

- 男女基礎體型分開。
- 四方向：正面、背面、左側、右側；每方向至少 idle 及 walk 兩幀，後續增加 run、attack、hit、cast。
- 裝備必須是獨立可穿戴圖層：髮型、頭部配件、上衣、褲子、鞋子、武器、飾品。不可將所有裝備烘焙成單一固定人物圖。
- 外觀與能力值分離：純外觀時裝可以不提供戰鬥數值。
- 職業初期：Warrior、Archer、Fighter、Mage。

## 核心遊戲循環

1. 在校園與周邊地圖探索。
2. 接取 NPC 任務、打怪及取得經驗與掉落。
3. 升級分配能力點、學習技能。
4. 取得／製作／強化裝備與時裝。
5. 組隊、聊天、交易及探索更高等級區域。

## 角色屬性與戰鬥

資料欄位建議：level、exp、hp、mp、sp、str、dex、int、con、attack、defense、moveSpeed、availablePoints。
技能資料需支援職業、需求等級、MP/SP 消耗、冷卻、射程、倍率、目標類型及效果標籤。
怪物資料需支援等級、HP、攻擊、防禦、經驗、金幣範圍、索敵距離、攻擊距離、重生時間及掉落表。
掉落機率以每個掉落項目獨立百分比判定；同一怪物多項掉落機率總和可以超過 100%。

## 資料管理原則

怪物、裝備、道具、技能、NPC、任務、掉落表應以資料檔管理。編輯器負責新增、編輯、刪除、搜尋、分類、匯入／匯出；遊戲 runtime 讀取同一資料 schema。正式連線版本再將本機資料遷移至伺服器資料庫。

## 開發里程碑

1. 2D 專案骨架、資料 schema、資料管理器。
2. Tile 地圖渲染、碰撞、四方向角色控制。
3. 可拆層人物與換裝預覽。
4. 怪物、即時戰鬥、技能、掉落。
5. 任務、NPC、背包、商店、強化。
6. 帳號、角色存檔、多人同步、聊天及組隊。
